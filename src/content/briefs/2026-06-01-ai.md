### NVIDIA ships Cosmos 3, an open omni-model for physical AI reasoning

> **Summary.** NVIDIA's *(GPU / AI silicon and software stack)* Cosmos 3 is a single open-weight model that handles physical-AI tasks: reasoning about scenes, predicting dynamics, and generating actions for robotics and autonomous systems. It ships as an "omni-model" — one architecture trained across perception, prediction, and planning rather than pipelined specialist models. NVIDIA is positioning it as a foundation model for embodied AI, analogous to what Llama did for language.

The Hugging Face post frames this as a shift from "generative AI" to "physical AI," which is NVIDIA's preferred taxonomy for selling more GPUs into robotics workloads. The technical claim is interesting if true: a unified model that reasons about 3D scene structure, predicts future states, and outputs control signals would eliminate a lot of fragile hand-engineered robotics stacks. But "omni-model" is NVIDIA's marketing term, not a benchmark category, and the HF blog is essentially a partner announcement. We need third-party evals on real robot platforms — likely months away — before we know if this generalizes or if it's a strong narrow model dressed in ambitious language. The open-weights release matters; NVIDIA has historically kept its best models gated behind NeMo and enterprise contracts.

([Hugging Face Blog](https://huggingface.co/blog/nvidia/cosmos-3-for-physical-ai))

### Anthropic documents Claude's sandbox architecture across products

> **Summary.** Anthropic published a technical overview of how it isolates Claude across three surfaces: Claude.ai *(web chat interface)*, Claude Code *(terminal-based coding agent)*, and Cowork *(enterprise multi-agent system)*. The post details process sandboxes, VMs, filesystem boundaries, and egress controls — the kind of concrete security engineering documentation that is rarely public from AI labs.

Willison's framing is right: sandboxing products are usually black boxes, and "trust us" isn't verifiable. Anthropic's decision to expose the mechanism — credentials never entering the sandbox, hard boundaries on what agents can reach — is a meaningful deviation from industry norm. The evidence quality here is mixed: it's first-party documentation, so we can't independently verify implementation fidelity, but the specificity is unusually high. They name techniques (gVisor, seccomp-bpf) and failure modes rather than gesturing at "enterprise-grade security." The gap is operational: we don't know how these controls perform under adversarial prompting or whether Cowork's multi-agent coordination introduces new escape surfaces. Still, this sets a benchmark that OpenAI and others will be pressured to match.

([Simon Willison](https://simonwillison.net/2026/May/30/how-we-contain-claude/) · [Anthropic](https://www.anthropic.com/) *[primary post, linked via Willison]*)

### OpenAI ships two first-party items: Boston Children's rare-disease diagnostics, Braintrust's Codex integration

> **Summary.** OpenAI published two case studies in close succession: one with Boston Children's Hospital using its models to diagnose 40+ rare diseases, another with Braintrust *(AI evaluation and experimentation platform)* on using Codex *(OpenAI's code-generation agent, distinct from the earlier GPT-4-family model of same name)* with GPT-5.5 for faster experimentation. Both are typical of OpenAI's current communications strategy: partner wins rather than model releases.

The Boston Children's item is stronger on social proof than methodology. "Helped diagnose" is doing heavy lifting — we don't know false-positive rates, how many cases were screened to find 40 successes, or whether clinicians were blinded. It's promising but sits in the familiar gap between pilot study and clinical deployment. The Braintrust post is more technically substantive: it shows how Codex with GPT-5.5 handles the full experimentation loop (generate hypothesis → write code → run → analyze), which matters for teams doing iterative ML work. But it's also a usage story for a product OpenAI wants to sell. Clustering these because they're both OpenAI communications output from the same 48-hour window; neither justifies standalone treatment given no new model or feature release.

([OpenAI News](https://openai.com/index/boston-childrens-hospital) · [OpenAI News](https://openai.com/index/braintrust))

### DeepSeek watch: Simon Willison's May note that "AI got expensive"

> **Summary.** Willison's May newsletter flagged that "AI got expensive" alongside noting Anthropic's strong month and that model releases "were a little disappointing." He also shipped Datasette Agent *(open-source natural-language interface for SQLite databases, built on LLM tool-calling)* and Datasette 1.0a32.

This is worth surfacing per the DeepSeek / open-weights watchlist mandate, even as indirect signal. Willison's "AI got expensive" observation tracks with broader pricing pressure: inference costs for frontier models aren't falling as fast as 2024, and companies are consolidating subscriptions rather than proliferating them. His Datasette Agent release is the more concrete item — a shipped tool that democratizes structured-data querying via conversation, with self-correcting SQL generation and visualization plugins. The 1.0a32 release is minor (bugfixes for RETURNING queries and Service Workers), but the ASGI-in-browser experiment via Pyodide + WebAssembly is the kind of technical exploration that often precedes platform shifts. Not headline-grade individually, but clustered as a signal on where open-source AI tooling is heading: cheaper to run locally, harder to monetize via API.

### GitHub Copilot switches to token-based billing, developer pushback follows

> **Summary.** Microsoft is replacing Copilot's flat-rate subscription with token-based billing, where developers pay per token consumed. The TechCrunch piece captures immediate developer consternation; the framing is that this ends Copilot's "golden age" of predictable pricing.

The anger is understandable but the economics were never sustainable. Flat-rate billing for a product whose marginal cost is inference tokens was a customer-acquisition subsidy, not a long-term equilibrium. Microsoft's move is rational price discrimination: heavy users will pay more, light users might pay less, and the company captures more of the value it creates. The "consternation" is mostly about surprise and billing unpredictability, not necessarily higher total cost — though for some power users it will be. What's thin here is any data on actual price changes; the piece leans on quoted complaints rather than modeled scenarios. Still, this matters as a bellwether: if Copilot can't make flat-rate work, neither can most AI coding tools, and the industry is shifting to usage-based whether developers like it or not.

([TechCrunch](https://techcrunch.com/2026/05/30/what-a-joke-github-copilots-new-token-based-billing-spurs-consternation-among-devs/))
